# B-roll Candidate Extraction

用于判断用户输入是否已经适合作为独立 B-roll 制作单元，并在需要时对原文进行候选提取或进一步分段。

## 输入路由

先判断输入形式，再判断每个待制作单元是否已经满足以下条件：

- 语义完整；
- 只有一个主要视觉命题；
- 能够独立形成明确 B-roll；
- 时长目标接近约 5 秒。

满足时直接进入 Gate 1；不满足时，按本文件规则执行 Candidate Extraction 或分段复核。

### Type A：单段约 5 秒口播

如果当前单段天然已经是一个语义完整、只有一个主要视觉命题的约 5 秒制作单元，直接作为一个 item 进入 Gate 1，不拆分、不筛选。

如果当前单段虽然较短，或可以被理解为一篇很短的完整定稿口播，但内部实际包含多个能够独立成立的主要语义或视觉命题，则执行分段复核：

→ 理解完整原段  
→ 按本文件的候选判断、原文规则与候选边界确定连续原文分段  
→ 将建议拆分结果按“第一段、第二段、第三段……”完整展示给用户  
→ 等待用户选择

用户可以：

- 保留原段作为一个 item，直接进入 Gate 1；
- 接受建议拆分，并让全部分段进入 Gate 1；
- 接受建议拆分，但只选择其中部分分段进入 Gate 1。

未被用户选择的分段不进入 Gate 1。

### Type B：用户已经拆好的多段口播

先尊重用户提供的原始分段，再逐段判断每一段是否已经是语义完整、只有一个主要视觉命题的独立制作单元。

符合条件的原段直接作为独立 item 进入 Gate 1。

如果其中一个或多个原段仍包含多个独立主要语义或视觉命题，则仅对这些原段执行分段复核：

→ 保留对应原段作为原始边界  
→ 按本文件规则确定该原段内部的连续原文分段  
→ 将建议拆分结果按“第一段、第二段、第三段……”完整展示给用户  
→ 等待用户选择

对于每个被建议继续拆分的原段，用户可以：

- 保留原段作为一个 item，直接进入 Gate 1；
- 接受建议拆分，并让全部分段进入 Gate 1；
- 接受建议拆分，但只选择其中部分分段进入 Gate 1。

未被用户选择的分段不进入 Gate 1。

如果用户通过编号、独立段落、明确 segment / item 标记，或明确表达“这些是我拆好的多段”提供多个制作单元，则按 Type B 处理。不得无理由重新划分已经符合制作单元条件的原段。

如果只是完整文章的自然换行，并非用户明确划分的制作单元，则仍按 Type C 判断。

### Type C：完整定稿口播

对于尚未被用户划分为独立制作单元的完整定稿口播，执行 B-roll Candidate Extraction。

流程：

完整口播  
→ 理解全文  
→ 找出值得独立制作 B-roll 的语义片段  
→ 确定连续原文边界  
→ 整理为约 5 秒制作单元  
→ 去除重复或弱候选  
→ 只展示最终候选  
→ 用户选择  
→ Selected Items 进入 Gate 1

不要求候选覆盖全文。

## 候选判断

候选首先必须满足两个硬条件：

1. **独立性**：脱离前后文仍能基本理解其完整意思。
2. **视觉性**：能够形成明确的人物、物件、动作、关系、过程、空间结构或状态。

通过后，再优先选择：

- 有明显变化、过程、对比、因果、选择或角色分工的内容；
- 全文中的核心观点、关键转折、重要论据或结论；
- 与其他候选在语义和视觉方向上有明显差异的内容。

降低以下内容的优先级：

- 单纯开场钩子；
- 语气填充；
- 普通过渡；
- 高度依赖上下文的承接句；
- 重复解释；
- 缺乏明确视觉关系的泛化抽象表达。

## 原文规则

所有候选或建议拆分段都必须来自对应用户原文中的连续片段。

不得：

- 改写；
- 总结后替换原文；
- 新增口播；
- 删除中间文字后重新拼接；
- 跨越不同位置拼接；
- 调换原文顺序。

内部可以总结核心意思用于判断，但展示给用户并送入 Gate 1 的内容必须保持用户原文。

## 候选边界

候选或建议拆分段的目标长度约为 5 秒，但语义完整性优先于严格时长。

优先级：

1. 完整语义；
2. 自然语言边界；
3. 单一主要视觉命题；
4. 接近约 5 秒。

过短时，可与相邻连续原文合并，但合并后仍必须只有一个主要视觉命题。

过长时，优先寻找自然语义边界；如果强拆会破坏意思，可以适度超过 5 秒。

不得为了接近 5 秒而机械按字数、句号或固定时间切分。

## 去重

如果多个候选：

- 核心意思高度相似；
- 很可能产生相同视觉隐喻；
- 承担相同叙事作用；

只保留更具体、完整、重要且视觉表达更强的一段。

不设置固定候选数量。

Type A / Type B 的局部分段复核以确定原段内部的合理语义边界为目的，不因去重规则擅自删除原段中的内容；最终保留哪些分段由用户决定。

## 用户选择

Type C 默认只向用户显示最终候选原文及编号，不显示内部评分和淘汰过程。

Type A / Type B 需要进一步分段时，向用户同时保留“按原段制作”和“按建议拆分制作”的选择。

用户可以：

- 保留原段；
- 全选建议分段；
- 选择一个建议分段；
- 选择任意多个建议分段。

只有用户最终选择的制作单元进入 Gate 1。

Candidate Selection 或分段确认只决定哪些原文单元进入制作，不是视觉设计 approval gate，也不能替代 Gate 1 的视觉确认。

候选提取与分段复核阶段不得提前设计正式视觉隐喻、具体物件组合、底色、组装顺序或 imagegen prompt。
